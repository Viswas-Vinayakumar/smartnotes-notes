5Quality criteria: correctness, accuracy, efficiency, reliability

  • What separates students who get the same use case and process is not complexity but their level of correctness, i.e. how deep they go and whether they revise, verify and balance their work.

43Writing guidelines: the Input–Process–Output cycle

  • Every document you write is for someone else to read, and that person should be able to execute it without knowing what you did.
  • Blocks of text followed by code at the end cannot be followed.
  • A guideline lets a company see and reuse your work, modify each step, and run it even when you are not there; this shows you are ready to engage.
  • Each step has three stages: (1) Input: define what you need; (2) Process; (3) Output.
  • The output of one step becomes the input of the next step. This chain is what the guideline describes.
  • A document built this way is 'usable': it can be handed to someone else and reused, and it is easy to convert into any format.
  • Versioning inputs within a step: input version 1, input version 2, with the change shown in the process box.

44Source Code Management and as-is / to-be process engineering

  • In industry this is called Source Code Management (SCM).
  • A complete first project document is 'as-is version 1'.
  • 'As-is version 2' is the update, modification or error fix applied to version 1. The document should show how many updates led to version 2 and what was added or modified, up to the new output.
  • What lies between as-is version 1 and as-is version 2 is the 'to-be'.
  • As-is to-be (process engineering): a structured method used to analyse how a workflow currently operates and then design a better, more efficient future version of it.
  • Search keywords: as-is to-be process, input-process-output cycle, source code management (managing the project).

Glossary 35

Anomaly
Something that happens and you cannot define it – something unknown, in between normal and abnormal; it cannot be used to confirm it is normal or indicate what it is. Not an error. 1:38

The justification and formula for why particular features are related to decide whether a condition (e.g. stress) exists or is normal, checked by augmenting or simulating what the readings are supposed to look like. 1:37

The output of the feasibility study: what exists and is best in industry, which your work has to reach or go above. 12:10
Build–Measure–Learn loop
Continuous cycle: build a model able to measure what you decide, measure the selected features, learn, implement changes and rebuild/measure again. 3:42

Said as 'confusion metrics' in the recording; a table of true positives, false positives, false negatives and true negatives. 1:48
